# Матрица тестирования и критерии приёмки

Внешние тесты — чёрный ящик против работающего стенда (`labctl test`, pytest).
Каждый запрос несёт `t=<uuid>` в URI, и событие ищется по нему: тест нельзя
пройти на вчерашних событиях или чужих записях (L3 ревью 0.14.2). Тесты,
которым нужна реальная блокировка, идут только с `LAB_ENFORCE=1` и в `finally`
восстанавливают dry-run и снимают блок.

| Файл | Маркер | Что проверяет |
|---|---|---|
| `test_00_stack` | smoke | слушатели, каждый vhost отвечает, health сервисов, HTTPS |
| `test_10_waf` | waf | XSS/SQLi/traversal/RCE → 403; легитимный admin-save → 200; ModSecurity записал запрос |
| `test_20_warden_waf` | warden | `waf.hit`/`security.waf_attack` по адресу, `site` в событии |
| `test_25_ipv6` | ipv6 | ротация внутри одной /64 → один блок `…/64` (N25) |
| `test_30_enforce` | enforce | настоящий блок атакующего, клиент работает, unblock |
| `test_40_fim` | fim | вебшелл в `uploads/` → `security.webshell` | Включая `svc-*` microservice roots.
| `test_45_spawn` | spawn | `/spawn` рантайма → `security.web_spawn` его пользователя |
| `test_50_forgery` | forgery | подделанная запись не блокирует чужой адрес (N4/N5) |
| `test_70_health` | health | health-проверки настроены на сервисы и БД |
| `test_90_journal` | warden | в окне нет неожиданных событий и ложных срабатываний |

Юнит-тесты самого `labctl` (`tests/unit/`, без root и стенда): загрузка
профиля, матрица совместимости, движок шаблонов, отрисовка всех профилей,
валидность генерируемого drop-in как TOML.

## Критерии приёмки (из плана 0.15)

- **Шлюз A (0.14.3):** `block_storm` — kill p99 < 50 мс, ни одно сдерживание не
  потеряно; 10 000 блоков < 5 с; у предела `max_blocked` < 5 мс на адрес;
  `waf_v6_spread` — один блок /64, IPv4 без изменений.
- **soak** (`labctl soak --hours 72`): наклон RSS после прогрева < 1 МиБ/сутки,
  `NRestarts = 0`, ни одного выброшенного события с приоритетом ≥ 3, ни одного
  `warden.worker_panic`.
- **Обновление** (`labctl test-upgrade`): пакет N-1 с настроенными drop-in →
  обновление до N → сохранность конфигурации, lineage, override dry-run и
  карантина → откат; с битым drop-in обновление отказывает, сервис жив.

## Проверено на стенде (этот выпуск)

- Профиль `ci-nginx-modsec3`: все 6 режимов WAF дают валидный `nginx -t` и
  применяются; XSS/SQLi/traversal блокируются (403), легитимный admin-save
  проходит (200), загруженный PHP в `uploads/` не исполняется (403); все 6
  движков отвечают своей идентичностью; микросервисы (node, python-asgi,
  php-fpm) отвечают по контракту за `/svc/<имя>/`; HTTPS работает.
- Профиль `apache-modsec2`: Apache prefork + mod_php + ModSecurity 2.9 —
  блокировка работает, аудит-лог `root:adm 0640` (не подделываемый веб-воркером,
  N5), `apachectl configtest` проходит.
- Профиль `haproxy-edge`: внутренний nginx + ModSecurity 3 + `haproxy -c`
  валидны (цепочка X-Forwarded-For).
- `apply` идемпотентен; `reset` снимает все отслеживаемые пути; смена профиля
  удаляет осиротевшие файлы предыдущего (L1).
- `pytest -m "smoke or waf"` — 10/10 проходит против живого стенда;
  тесты, требующие Warden, корректно пропускаются без демона; юнит-тесты 12/12.

Полное покрытие произвольных инцидентов не гарантируется: результат зависит от
CRS, конфигурации приложения, возможностей ядра, правил Warden и корпуса
испытаний.
