# Доступ к Warden Lab Kit из локальной сети

Профиль `ci-nginx-modsec3` намеренно работает в режиме `loopback`. Чтобы
открывать портал из браузера на другой машине без SSH-туннеля, используйте
режим `lan`. Он разрешает HTTP/HTTPS только от указанных в `net.trusted`
адресов/подсетей на одном выбранном интерфейсе; порты микросервисов остаются
закрытыми снаружи. Не используйте `0.0.0.0/0`, если не хотите открыть стенд
всем IPv4-адресам.

## 1. Определить интерфейс и адреса

На сервере:

```bash
ip -br addr
ip -4 route
```

`external_iface` — интерфейс сервера, через который приходит соединение с
хостовой машины (например, `ens18`, `enp0s3` или `eth0`). `trusted` — IP/CIDR
**клиентской машины**, с которой будешь открывать браузер, а не адрес сервера.
Безопаснее разрешить один адрес, например `192.168.1.100/32`. Если надо открыть
доступ всей доверенной подсети, используй её реальный CIDR, например
`192.168.1.0/24`. Примеры адресов нужно заменить на свои.

Если сервер виртуальный и неясно, какой source IP до него доходит, можно
временно наблюдать подключения на сервере (если установлен `tcpdump`):

```bash
sudo tcpdump -ni any 'tcp dst port 80 or tcp dst port 443'
```

Запусти запрос с хостовой машины и используй увиденный source IP в `trusted`.

## 2. Изменить `lab.toml`

Сделай резервную копию:

```bash
cp lab.toml "lab.toml.before-lan.$(date +%Y%m%d-%H%M%S)"
```

Открой `lab.toml` и замени существующую секцию `[net]` на значения ниже,
подставив реальные интерфейс и IP/CIDR:

```toml
[net]
mode = "lan"
external_iface = "ens18" # заменить на интерфейс сервера
trusted = ["192.168.1.100/32"] # заменить на IP хостовой машины
v4_cidr = "10.77.0.0/24"
v6_cidr = "fd77::/64"
```

Если в существующем профиле `v4_cidr` и `v6_cidr` отличаются, оставь их
прежними. Не создавай вторую секцию `[net]` — отредактируй существующую.

В комплекте также есть пример `profiles/lan-nginx-modsec3.example.toml`.

## 3. Проверить план и применить

Из каталога проекта:

```bash
sudo ./labctl plan
sudo ./labctl apply --no-packages
sudo nginx -t
sudo nft list table inet lab_filter
sudo ./labctl verify
```

`--no-packages` пропускает повторное выполнение APT, поскольку пакеты стенда
уже установлены. При первом запуске LAN-режима внимательно проверь сгенерированные
правила перед применением профиля. Nginx будет слушать порт 80 и HTTPS-порт 443;
правила `inet lab_filter` ограничат доступ по интерфейсу и `net.trusted`.

## 4. Открыть сайт с хостовой машины

Обычный профиль Nginx слушает **80/443**, не `8080`. Укажи в hosts-файле
хостовой машины, что `lab.local` соответствует IP-адресу Ubuntu Server, и открой:

- `http://lab.local/`
- `https://lab.local/` (самоподписанный сертификат вызовет предупреждение браузера)

Для WordPress и OpenCart добавь при необходимости соответствующие имена:
`wordpress.lab.local` и `opencart.lab.local`. Запись `hosts` для профиля по
умолчанию может выглядеть так (замени IP сервера):

```text
192.168.56.110 lab.local wordpress.lab.local opencart.lab.local
```

## 5. Проверить, что слушает порт 8080

Если `http://lab.local:8080/` продолжает отвечать `426 Upgrade Required`, это
не ожидаемый адрес прямого доступа для данного nginx-профиля. На сервере выполни:

```bash
sudo ss -ltnp '( sport = :8080 )'
sudo ss -ltnp '( sport = :80 )'
sudo ss -ltnp '( sport = :443 )'
```

Порт 8080 должен использоваться только если выбран edge-front (HAProxy/Caddy)
или отдельно настроен проброс портов. Не меняй режим LAN на `external` только
ради доступа из браузера: `external` предназначен для публичного фронта и не
эквивалентен LAN-only allowlist.
